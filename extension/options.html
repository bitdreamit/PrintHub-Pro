Behavior

Print every PDF opened in the browser (simple mode)

ANY PDF you open - any site, any URL - is printed silently and its tab closes. No print view, no dialog, no rules needed. Turn off to auto-print only URLs matching your rules below.

Intercept window.print()

Web apps (Odoo, POS, dashboards) that call window.print() are printed silently through the hub instead of opening the dialog. Also intercepts Ctrl+P / Cmd+P.

Close tab after auto-print

When a rule auto-prints an opened URL, the tab is closed right after the job is queued - zero browser view, the paper just comes out. Off by default since v1.7.0 so tabs stay open; turn it on for a kiosk-like flow.

Never auto-print on these sites

One host per line (e.g. example.com). Rules and "print every PDF" skip these sites - the quick way to silence a chatty system. You can also toggle the current site from the popup button or the right-click menu.

When a page print call fails

Controls the automatic fallback of printPdfLink() / printPdf() on web pages: if the hub cannot print a PDF (hub off, printer error, not a PDF), either open the URL in a normal tab so the browser prints it the default way, or stay completely silent - nothing opens, the failure is only logged in the job history. A per-call opts.fallback (true/false) in page JS overrides this setting.

Windows service - run before logon

Install PrintHub Pro as a real Windows service: it appears in services.msc as "PrintHub Pro Service", starts at BOOT before anyone logs in, and restarts automatically if it crashes. In service mode there is no tray icon (Windows rule for services) - manage it in services.msc, here, or the status page.

Installing pops a one-time Windows admin (UAC) prompt - confirm it and you are done; the service is compiled on your PC from hub\service\PrintHubProService.cs with your own Windows csc.exe (nothing is downloaded). Prefer files? Run install\INSTALL-WINDOWS-SERVICE.bat or REMOVE-WINDOWS-SERVICE.bat. CLI: PrintHubPro.exe hub\printhub.py service install|remove|status.

Developer API - window.printhub

Available on every page (when the hook is enabled). All methods return Promises.

<script>
  await window.printhub.status();            // hub health
  await window.printhub.printers();          // [{name, is_default}]
  await window.printhub.printPage({title});  // print current page
  await window.printhub.printPdf(url, {title, printer});
  await window.printhub.print({
    title: 'Receipt 12', printer: '', copies: 1,
    text: '|center|HELLO|',        // or:
    html: '<h1>Invoice</h1>',      // or:
    pdfBase64: 'JVBERi0...',       // or:
    pdfUrl: 'https://.../report.pdf'
  });
</script>
Direct HTTP also works from any language: POST http://127.0.0.1:9235/print with header X-PrintHub-Token - see docs/API.md in the package. Raw binary upload: POST the PDF bytes to /print?title=...&fit=noscale with Content-Type: application/pdf.
