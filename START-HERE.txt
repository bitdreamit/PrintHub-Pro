WHAT'S NEW IN 2.6.4 (WINREG FIX - WINDOWS HEALTH/DEBUG/PRINT BACK)
  1. /HEALTH STUCK ON "starting": true - ROOT-CAUSE FIXED.
     The hub used the Windows registry module (winreg) in the
     SumatraPDF lookup without importing it. On Windows that raised
     NameError every time; the /health snapshot never filled and the
     hub answered the tiny fallback forever. Fixed: the import is
     guarded and the full snapshot (31 fields) fills within seconds.
  2. /DEBUG + /DIAGNOSTICS "didn't send any data" (ERR_EMPTY_RESPONSE)
     - SAME ROOT CAUSE. Both endpoints call the same lookup; the
     crash killed the connection before a single byte was sent.
     Both return full JSON again.
  3. PDF PRINTING ON WINDOWS WAS SILENTLY BROKEN by the same bug
     (the lookup is on the print path). Now crash-proof.
  4. A HUB BUG CAN NEVER AGAIN LOOK LIKE "connection reset": every
     request is wrapped - an unexpected error answers a readable
     message and the traceback lands in hub.log + the audit trail.
  5. STALE TOKEN REPAIRS ITSELF: a browser opening the dashboard
     with an old token is redirected (302) straight to the working
     page with the current token. Old bookmarks just work. The
     extension keeps auto-syncing the token silently.
  6. SETUP KILLS ZOMBIE HUBS by image name (AdvPrintPro.exe and the
     legacy name) - a hub on any port cannot survive an upgrade with
     an old token in memory.
