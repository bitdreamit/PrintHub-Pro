WHAT'S NEW IN 2.6.3 (INSTANT HEALTH + TRAY 64-BIT + LOCKOUT FIX)
  1. "HUB DID NOT ANSWER WITHIN 20 SECONDS" - FIXED FOR REAL.
     Cause: the hub's /health check ran slow Windows printer scans
     (PowerShell/WMI) on the request path, so the hub could listen
     on port 9235 while no probe ever got an answer in time
     (hub.log said "listening", the tool said "not answering",
     the extension said OFFLINE). /health is now an instant,
     precomputed snapshot - no slow scan can ever block it again.
  2. TRAY ICON NOW REALLY APPEARS ON 64-BIT WINDOWS. The log line
       [TRAY] tray unavailable: ArgumentError('argument 11:
       OverflowError: int too long to convert')
     was a 64-bit ctypes bug (truncated module handle). All win32
     calls now carry exact prototypes - icon, dark menu, tooltip
     and auto-run check all work.
  3. YOUR OWN PC CAN NEVER LOCK YOU OUT ANY MORE. The dashboard
     error "too many failed tokens - this IP is locked for another
     124s" could hit 127.0.0.1 itself when the exemption was off.
     Loopback is now unconditionally exempt, hard-coded.
  4. NO MORE DOUBLE HUB. Two hub processes could share port 9235
     (two BOOT lines in hub.log). The port is now bound
     exclusively; a second start exits with a clear log line.
  5. INSTALLER NOW ASKS FOR ADMIN LIKE A REAL DESKTOP APP: the
     setup installs per-machine into Program Files and Windows
     shows the UAC prompt automatically. Upgrades clean up the
     old per-user copy. If SumatraPDF (the PDF print engine) is
     missing, the installer installs it silently via winget.
  6. NEW TRAY ICON: deep brand blue with a white printer and a
     green ready dot - visible on light AND dark taskbars.
  7. THE CONSOLE TOOL AND THE EXTENSION TELL THE TRUTH: the tool
     waits up to 30 s and says when the port is already up; the
     extension shows OFFLINE / HUB STARTING / TOKEN PROBLEM as
     three different states.

WHAT'S NEW IN 2.6.2 (EXTENSION + TRAY FIX RELEASE)
  1. EXTENSION "OFFLINE" WHILE THE DESKTOP TOOL SHOWS "RUNNING" -
     FIXED FOR GOOD. Cause: the extension kept an OLD hub token in
     its storage (the hub had a different one), the hub answered
     401, and the popup mislabeled that as "OFFLINE - start the hub
     first". Now:
       - the extension AUTO-HEALS: on the first 401 it silently
         asks the RUNNING hub (same PC) for the current token,
         stores it and retries - you do nothing.
       - the popup now says "Hub running - token mismatch" instead
         of the wrong "offline", and the token banner has a
         one-click "Fix token" button as a manual backup.
  2. TRAY MENU TEXT INVISIBLE (WHITE ON WHITE) - FIXED. On PCs with
     shell replacements / custom themes the native menu inherited
     shell colors and showed white text on a white box. The menu is
     now drawn by AdvPrint itself: dark navy, white text, blue
     hover, green checks - identical on every PC and every theme.
  3. SECURITY: the token-pairing endpoint (/token/current) can no
     longer be read by web pages (CORS locked); only the extension
     and programs on the hub PC can use it.
  4. The extension version you see anywhere (page API, popup,
     options) now always equals the manifest version - one source.

WHAT'S NEW IN 2.6.1 (HUB START + TRAY FIX RELEASE)
  1. "HUB OFFLINE" IS NOW SELF-DIAGNOSING AND SELF-HEALING:
       - the desktop tool (AdvPrint-Tool.bat / Start Menu "AdvPrint
         Tool") got a new menu item [13] "Diagnose & fix". One pick
         and it: checks the install folder, UNBLOCKS every file
         (Windows marks files of a downloaded zip as blocked - a
         common reason the hub exe "never answers"), frees the port
         from old zombie instances, then starts the hub in PLAIN
         VIEW so any remaining error shows as readable text.
       - when a normal start fails, the tool now prints WHY right
         in the window: port state, process state, the last 20
         lines of hub.log, and a copy/paste start command with the
         REAL full path (a plain "python advprint.py serve" from
         C:\Users\<you> can never work - the file is not there).
       - the hub logs [BOOT] lines for every start and writes ANY
         crash into hub.log, so "hub offline" always comes with the
         reason on paper.
  2. TRAY ICON FIXED: the bundled runtime runs Python in isolated
     mode and did not see the tray module in the portable layout -
     the hub ran but the icon never appeared. Fixed; the tray
     "AdvPrint Pro" icon now appears next to the clock whenever the
     hub runs (Open dashboard / test page / pause / auto-run /
     exit). It can hide under the ^ arrow near the clock.
  3. DASHBOARD FIXED FOR REAL: a single broken quote in the LAN
     card made the WHOLE dashboard JavaScript fail to parse since
     v2.2 - tables stayed empty ("-") and buttons did nothing
     ("idle - click the button above"). Fixed; the script is now
     syntax-checked on every build and smoke run. The live test
     tool shows the REAL version (was stuck "v2.5") and every
     button plainly says when the hub is offline.
  4. STILL OFFLINE? 60-SECOND FIX, NO CONSOLE SKILLS NEEDED:
       a. open the tool (AdvPrint-Tool.bat, or Start Menu >
          AdvPrint Pro > AdvPrint Tool)
       b. pick [13] Diagnose & fix -> read the [4/5] result
       c. pick [1] Start -> "Started: v2.6.1 on http://127.0.0.1:9235"
       d. tray icon appears -> right-click -> Open dashboard
     If [13] says antivirus: add the AdvPrint folder to your AV's
     exclusions and start again (menu [1]).

THE TOKEN
  Fresh installs: a PRIVATE RANDOM token (shown once in hub.log,
  readable with "python "<install>\hub\advprint.py" token" or the
  config file). Upgraded pre-2.0 installs: old default
  PrintHub-2024 keeps working until you rotate it (the dashboard
  warns you). Lost it? Stale bookmark? -> the dashboard error page
  has the one-click fix, or tray -> Open dashboard, or extension ->
  Detect token. Rotate: dashboard "Rotate token" button.
