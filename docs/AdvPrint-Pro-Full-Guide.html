1. What AdvPrint Pro is — and how one print job travels

AdvPrint Pro (Advanced Printer) by Bit Dream IT — Innovative Healthcare Solutions prints anything — PDFs, web pages, window.print() calls, receipts (raw/ESC-POS), screenshots, selections — silently, with no print dialog, on any printer connected to the hub PC, including printers shared from other PCs. Everything stays on your machines: the hub listens on 127.0.0.1:9235 only (until you deliberately enable LAN sharing), no cloud, no telemetry.

Product identity: AdvPrint Pro — AdvPrint (Advanced Printer) — by Bit Dream IT — Innovative Healthcare Solutions. The hub reports app: "AdvPrint Pro" and the full brand string in every /health answer.

2. Install in 3 minutes

2.1 Windows — the one-time installer (recommended)

  1. Download AdvPrint-Pro-v2.6.2-FULL.zip and unzip it.
  2. Run AdvPrint-Pro-Setup-2.6.2.exe. No admin needed, no UAC popup, no Python needed — the setup carries a complete Python 3.11.9 runtime (this is exactly what the broken 2.5.3 download missed: if an installer is smaller than ~9 MB it is incomplete — re-download).
  3. Setup registers the Startup app "AdvPrint Pro" (Task Manager → Startup apps), creates Start Menu shortcuts, and starts the hub. A tray icon A appears next to the clock.
  4. Optional ticks: Run as Windows service (headless, services.msc) and Install browser extension files.
Windows says "cannot access / Access is denied" on a downloaded setup? That is Mark-of-the-Web on a damaged/incomplete download. The 2.6.x setup is complete (~9.6 MB) and the portable install\install-windows.bat unblocks every file automatically. If your AV quarantines the hub, whitelist the folder %LOCALAPPDATA%\AdvPrintPro — the hub is a plain stdlib Python script, signed-off and open source (MIT).

2.2 Windows — portable zip (no installer)

  1. Unzip. Double-click tool\windows\portable\install\install-windows.bat. It unblocks files, frees port 9235, uses the bundled runtime, registers auto-run, health-checks the hub.
  2. Undo any time: UNINSTALL-WINDOWS.bat.

2.3 Linux / Debian / Ubuntu / Mint — the .deb

sudo apt install ./advprint-pro_2.6.2_all.deb
advprint-start            # start now
advprint token            # show the current token
advprint livetest         # full A-to-Z self-test

Auto-run at login: run /opt/advprint/install/install-unix.sh (installs a systemd --user service — no root needed; falls back to XDG autostart). Headless server mode: sudo /opt/advprint/install/install-unix.sh --service.

2.4 macOS

Run the portable hub: python3 tool/unix/hub/advprint.py serve, then install-unix.sh (LaunchAgent auto-run). CUPS printers are used through lp; page printing uses Chrome/Edge if installed.

2.5 First print in 60 seconds

  1. Hub running (tray icon green / advprint status).
  2. Load the extension: chrome://extensions → Developer mode → Load unpacked → the extension folder (or the one installed to %LOCALAPPDATA%\AdvPrintPro\extension).
  3. Open the extension Options → Settings → Detect token (one click) → Connect shows CONNECTED.
  4. Click Send test page. Paper comes out. Done.

3. The token — and the one-click fix

Every request to the hub carries a token. Since v2.0 a fresh install generates a private random token and stores it in %USERPROFILE%\.advprint\config.json (Linux/macOS ~/.advprint/config.json). Upgrades of pre-2.0 installs keep working with the old default PrintHub-2024 until you rotate it — the hub warns you in the dashboard until then. Pre-2.6 installs with a ~/.printhub folder are migrated automatically to ~/.advprint on first start (old folder kept as backup).

3.1 The one-click fix (v2.6)

Open a stale bookmark like /dashboard?token=PrintHub-2024 and you get the friendly error page — with a green “Fix it now — open the dashboard with the current token” button. One click and you are in. It works because the hub hands the current token only to programs on the hub PC itself (loopback-only GET /token/current); other PCs on the LAN still see the manual steps only. The same button exists in the extension Options → Settings → Detect token.

4. The browser extension — every Options tab explained

Open the extension icon → ⚙ (or right-click the toolbar icon → Options). The Options page is tab-wise: Queue History Settings Debug LAN / PCs About. The extension opens on Queue when something is waiting, otherwise on Settings. Every tab auto-refreshes live.

4.1 Queue tab — live FIFO

  • Hub state dot: running / PAUSED / offline, pending count, jobs today, hub version.
  • Every waiting job row: id, title, printer, kind, status chip + buttons: Cancel, Shift to PC (print this job on another PC's hub over the LAN), Print now (bypasses pause and printer-status hold — the remedy when jobs sit "stuck").
  • Pause / Resume queue, Clear queue, Refresh. Auto-refresh every 3 s.

4.2 History tab — last 100 jobs

  • Every job with time, title, printer, kind and a colored status chip — queued gray, printed green, failed/dead/canceled red, held orange (with the exact held reason, e.g. "printer offline").
  • Row actions: Retry (failed jobs — optionally on another printer), Reprint (printed jobs — reason goes to the audit log), Cancel/Print now (waiting jobs).
  • History auto-refreshes every 8 s — a stuck "queued" row turns "printed" in front of you.
  • “Clear” wipes only the browser-side copy; the hub history stays.

4.3 Settings tab — all switches

  • Power switches: master AdvPrint enabled (OFF = nothing prints, gray OFF badge), Queue mode (ON = FIFO order + pause; OFF = instant print with auto-queue fallback), Debug mode, Retry when the hub comes back, UI language (English / বাংলা / auto).
  • Connection: Hub URL (http://127.0.0.1:9235), Token + Connect + Detect token; buttons to open the dashboard and the audit log.
  • Printing: default printer (or "File (save as PDF)"), plus default print options sent with every job: copies, pages (odd/even/custom), quality (draft…1200 dpi), per-sheet n-up, duplex, layout, scale, margins, paper size — with live capability hints from the selected printer.
  • Auto-print & routing rules: URL pattern (glob or regex), page-title filter, per-rule printer, action (auto/PDF/page), per-site ON/OFF, auto-print-on-open, delete. First match wins.
  • Behavior: print every PDF opened in the browser (simple mode), intercept window.print() (also Ctrl+P), close tab after auto-print, failure fallback (new tab vs silent), right-click menu, toolbar badge.
  • Hub settings (advanced) — v2.6: the hub's own switches, editable live (see §9 for the full list): queue & retries, security/lockout, reprint watermark & reason, audit, thermal text engine + ESC/POS codepage, save-as-PDF folder, keep-files, SumatraPDF path.

4.4 Debug tab — WHEN / WHY / WHERE

  • One card: hub version, debug mode on/off, worker alive, queue paused, printers ready, instant auto-queue state.
  • Problems found by the hub table with the exact fix for each finding.
  • Browser error reports: everything this browser hit (network, token, page JS) while Debug mode was on.
  • Buttons: Refresh · Send test report · Copy report (everything for a bug report) · Open /debug JSON · Run full self-test (A-to-Z) — runs the hub's live test right here and prints OK/!! lines (v2.6).

4.5 LAN / PCs tab — share & shift

  • Shows this PC's LAN URL (http://192.168.x.x:9235) when sharing is ON, with copy button.
  • Enable/Disable LAN sharing (writes share_lan; restart the hub to rebind + open TCP 9235 in the firewall).
  • Other PCs (peers): online/offline + version of each configured peer hub, one-click Shift all waiting jobs. Or type a LAN URL and shift everything ad hoc.

4.6 About tab

Version + full brand line, update check against GitHub releases, links to the user guide served by the hub (/docs), the developer API (window.advprint) and the test tools.

4.7 The popup (toolbar icon)

Master switch, queue mode switch, live queue state, pause/resume, last jobs, test page, screenshot-to-printer, save-page-as-PDF, offline banner with retry counter, token warnings with the exact remedy. Hotkey Alt+P prints the current tab. Right-click menu prints page / selection / linked PDF / screenshot.

6. Printing everything

6.1 PDFs (the lab-report flow)

  • Simple mode (default ON): any PDF opened in the browser prints silently and the tab closes.
  • Rules: URL pattern + optional title filter + optional printer → auto-prints the moment the URL opens (glob or regex).
  • From your app's code: printPdfLink(url, 'Lab report', {fallback:false}) — the page API prints via the hub and never opens a dialog. Full API: extension content/api.js, docs at /docs.

6.2 Web pages

Right-click → AdvPrint Pro → Print page · Alt+P · popup button · window.advprint.printPage(). Rendered with headless Chrome/Edge at print quality. window.print() and Ctrl+P are intercepted (toggle in Settings) and routed silently.

6.3 Receipts / raw text (ESC/POS)

Send kind:"raw" or |center|…| markup to /print. Codepage selectable (cp437/cp850/cp866/cp1251/cp1252). Bangla and other complex scripts are automatically rendered through headless Chrome so they shape correctly on thermal rolls (thermal_text_engine).

6.4 Selections & screenshots

Right-click a selection to print exactly it; the popup can print the visible page as an image — useful for POS systems and stubborn apps.

6.5 Save as PDF instead of paper

Choose printer File (save as PDF) or send "printer":"__file__". Files land in ~/Downloads/AdvPrint or the folder set in Hub settings (file_dir).

7. LAN / IP — share one printer with every PC

  1. On the printer PC: extension Options → LAN / PCs → Enable LAN sharing (or dashboard → LAN card). Restart the hub.
  2. Firewall: allow inbound TCP 9235 (Windows: netsh advfirewall firewall add rule name="AdvPrint Pro" dir=in action=allow protocol=TCP localport=9235 — run once as admin).
  3. On each client PC: install the extension, set Hub URL to http://<printer-PC-ip>:9235, press Detect token on the printer PC (or paste the token) → Connect.
  4. Every PC now prints to the shared printers; jobs can be shifted between PCs (single job or the whole waiting queue) when a PC goes down.
The token is required from every LAN PC — no token, no printing (the hub rate-limits and locks out foreign IPs after too many bad tokens, while your own PC (127.0.0.1) is never locked out by default).

8. Queue, History & Audit trail

  • Queue mode ON: jobs wait in FIFO order, Pause/Resume works, one job prints at a time.
  • Queue mode OFF (instant): each job prints immediately; if the printer is not active the job is auto-queued (instant_auto_queue) and prints when the printer is back.
  • Printer-status hold (hold_offline): jobs whose printer reports offline/paper-out are held with a reason and auto-print on recovery — or hit Release ALL held jobs / per-job Print now to force.
  • Retries: failed jobs retry with exponential backoff (max_retries × retry_base_seconds).
  • Duplicates: identical jobs inside dedupe_minutes are blocked (double-click protection).
  • History: last 100 jobs in the hub DB (SQLite) with per-job file for reprints (keep_files); export CSV from the dashboard.
  • Audit trail: who printed what, from which site/IP, reprint reasons, auth failures — CSV export too; disable with audit_enabled:false.

11. Enterprise edition — silent install, policy, service

11.1 Silent / scripted Windows install

AdvPrint-Pro-Setup-2.6.2.exe /S          # silent, per-user, no UAC
# enterprise rollout via Intune/GPO/SCCM: run per user, no elevation needed

11.2 Managed policy (force settings on all PCs)

Deploy extension/managed.json content as Chrome policy HKLM\SOFTWARE\Policies\Google\Chrome\ExtensionInstallForcelist + managed storage, or simply push the keys. Forceable settings: hubUrl, token, defaultPrinter, enabled, queueMode, retryOffline, lang, hookPrint, autoPrintAllPdfs, failFallback, closeAfterPrint, rules (rules fully override local ones — central lockdown). Managed values win over user settings.

11.3 Windows service mode (headless)

python advprint.py service-install     # UAC → registers services.msc: "AdvPrint Pro Service"
python advprint.py service-status / service-remove

Service mode = no tray, runs before logon, perfect for a print-server PC. The normal Startup app stays the default on desktops; if both run, the second exits gracefully (port guard).

11.4 Lockdown checklist

  • allowed_origins → only your web app may print.
  • token_header_only:true + rotated token on every PC.
  • share_lan:false everywhere except the print-server PC; that one keeps lockout_exempt_loopback and strict lockouts for foreign IPs.
  • audit_enabled:true + reprint_reason_required:true for compliance; audit CSV ships out nightly.
  • LAN firewall rule only where needed (§7).

12. HTTP API quick reference

Auth: header X-AdvPrint-Token (legacy X-PrintHub-Token accepted), or ?token= on GET navigation. Full docs: docs/API.md and the hub's own /docs page.

# status
curl http://127.0.0.1:9235/health
curl -H "X-AdvPrint-Token: $TOKEN" http://127.0.0.1:9235/printers
# print a PDF from bytes (silent)
curl -X POST -H "X-AdvPrint-Token: $TOKEN" -H "Content-Type: application/pdf" \
     --data-binary @report.pdf "http://127.0.0.1:9235/print?title=Report"
# print a page with options
curl -X POST -H "X-AdvPrint-Token: $TOKEN" -H "Content-Type: application/json" \
  -d '{"url":"https://intranet/roster","paper":"a4","duplex":"duplex","copies":2}' \
  http://127.0.0.1:9235/print
# queue control / tokens / settings
curl -X POST -H "X-AdvPrint-Token: $TOKEN" http://127.0.0.1:9235/queue/pause
curl -X POST -H "X-AdvPrint-Token: $TOKEN" http://127.0.0.1:9235/token/rotate
curl -H "X-AdvPrint-Token: $TOKEN" http://127.0.0.1:9235/config
# live test over HTTP (same check as the CLI)
curl -X POST -H "X-AdvPrint-Token: $TOKEN" http://127.0.0.1:9235/livetest

Page-side API (in any web page once the extension is installed): printPdfLink(url, title, opts) · window.advprint.printPdf/printPage/printers/status/history.

14. Upgrade, uninstall, files & folders

14.1 Upgrade

Run the new setup over the old one (same per-user location, settings/history kept) — or replace the portable folder. The extension updates by Remove + Load unpacked (or GitHub update check → new zip). Data folders migrate: ~/.printhub → ~/.advprint automatically.

14.2 Uninstall

Windows: Start Menu → Uninstall AdvPrint Pro (or Apps & features). Service: removed automatically. History/settings in ~/.advprint are kept (delete manually if unwanted). Linux: sudo apt remove advprint-pro + uninstall-unix.sh.
